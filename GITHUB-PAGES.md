# Как выложить сайт на GitHub Pages

Проект уже настроен: он собирается в обычные html-файлы, которые GitHub Pages умеет отдавать.
Ничего в коде менять не нужно — просто выполни шаги ниже.

## Шаг 1. Создай репозиторий

1. Зайди на github.com → кнопка **New repository**.
2. Имя любое, например `shkola-tancev`.
3. Видимость обязательно **Public** — на бесплатном тарифе Pages работает только с публичными.
4. Галочки вроде "Add README" ставить не надо.

## Шаг 2. Залей файлы

Распакуй архив. Важно: в корне репозитория должен лежать `package.json`,
а не папка `shkola-tancev` с ним внутри.

**Вариант А — через браузер (проще):**

1. На странице пустого репозитория нажми ссылку **uploading an existing file**.
2. Открой папку `shkola-tancev` и перетащи в браузер всё её содержимое.
3. Внизу нажми **Commit changes**.

Если папка `.github` не видна при перетаскивании (Мак и Windows прячут папки с точкой) —
включи показ скрытых файлов: на Маке `Cmd + Shift + .`, на Windows в Проводнике
вкладка «Вид» → «Скрытые элементы». Без этой папки автосборка не запустится.

**Вариант Б — через командную строку:**

```bash
cd путь/к/shkola-tancev
git init
git add .
git commit -m "Сайт школы танцев"
git branch -M main
git remote add origin https://github.com/ТВОЙ-ЛОГИН/shkola-tancev.git
git push -u origin main
```

## Шаг 3. Включи Pages

1. В репозитории открой **Settings** → слева в меню **Pages**.
2. В блоке **Build and deployment** в поле **Source** выбери **GitHub Actions**.
   Не выбирай "Deploy from a branch" — с ним сайт не соберётся.
3. Больше ничего не настраивай.

## Шаг 4. Дождись сборки

Открой вкладку **Actions**. Там будет запущенная задача «Deploy to GitHub Pages».
Сборка идёт 2–4 минуты. Когда появится зелёная галочка, сайт будет доступен по адресу:

```
https://ТВОЙ-ЛОГИН.github.io/shkola-tancev/
```

Ссылка также появится в Settings → Pages.

Дальше любое изменение файлов в репозитории автоматически пересобирает сайт.

## Как это работает

- `next.config.mjs` — включён режим `output: 'export'`: сборка создаёт папку `out/`
  с готовыми html-файлами без необходимости в Node.js на сервере.
- `.github/workflows/deploy.yml` — автосборка. Сам определяет имя репозитория
  и подставляет его в пути, потому что на Pages сайт лежит в подпапке.
- `scripts/fix-base-path.mjs` — после сборки дописывает префикс к путям
  картинок, шрифтов и курсоров и создаёт `.nojekyll`.

## Локальная проверка статики

```bash
npm install
NEXT_PUBLIC_BASE_PATH=/shkola-tancev npm run build:gh
npx serve out
```

На Windows в PowerShell переменная задаётся иначе:

```powershell
$env:NEXT_PUBLIC_BASE_PATH="/shkola-tancev"; npm run build:gh
```

Обычная разработка никак не меняется: `npm run dev` и http://localhost:3000

## Свой домен

Если подключишь собственный домен (Settings → Pages → Custom domain), сайт переедет
в корень и префикс станет лишним. Тогда в `.github/workflows/deploy.yml` в шаге
«Determine base path» замени содержимое на одну строку:

```yaml
        run: echo "NEXT_PUBLIC_BASE_PATH=" >> "$GITHUB_ENV"
```

## Частые проблемы

**Открывается текст без стилей.** Не залита папка `.github` или в Source выбран
«Deploy from a branch» вместо «GitHub Actions».

**Страница 404.** Сборка ещё идёт либо упала — смотри вкладку Actions.
Также проверь, что `package.json` лежит в корне репозитория, а не во вложенной папке.

**Не видно картинок или шрифтов.** Значит не отработал шаг с `fix-base-path.mjs`:
убедись, что папка `scripts` залита в репозиторий.

**Не играет видео на первом экране.** Это не связано с хостингом: ролик с Vimeo
привязан к домену исходного шаблона. Нужно положить своё видео в `public/hero.mp4`.
